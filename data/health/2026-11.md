# External dependency health, November 2026

Sweep date: 2026-11-01.

## Pipeline endpoint: ADS-B Exchange is blocking the collector

The main finding this month. The globe_history archive
(globe.adsbexchange.com/globe_history/...) has answered HTTP 403 to every request since
October 29: from the GitHub Actions runner (every scheduled run from October 29 10:52 UTC
onward failed, all 4 retries on every heatmap slice, 0 of 21 slices fetched) and from this
sweep's environment. The October 1 sweep got a 24 MB slice with HTTP 200 from the same
pattern, so this is a change on their side, not in the pipeline. The workflow itself is
healthy: it fires on schedule, fails at the fetch step, and exits before the commit step as
designed.

Consequences and follow-up:

- The last collected night is 2026-10-28. Every night since is uncollected, and the
  quiet-hours page is stale by the same span. Each missed night needs a manual backfill
  (python3 weekly.py --date YYYY-MM-DD) once the archive answers again.
- Whether the 403 is a bot wall in front of still-public data or a policy change (the
  archive moving behind the paid API) could not be determined from here; this environment's
  tooling cannot run a browser probe this month. Worth a manual look at
  globe.adsbexchange.com from a normal connection, and at their status/community channels,
  before deciding whether the pipeline needs a different source.
- If access does not return, the honest fix is a dated note on the quiet-hours page saying
  collection stopped and why. That changes what the page claims, so it is left to the
  maintainer rather than made in this sweep.
